Cette vidéo montre comment configurer Hermes Agent avec OpenRouter pour utiliser des modèles d’IA gratuits sans ordinateur puissant. Depuis un VPS ou une machine dédiée, elle détaille la création d’une clé API OpenRouter, son ajout à Hermes et l’utilisation d’un assistant comme Claude pour adapter les commandes. La démonstration crée ensuite Frida, un worker chargé de produire des B-rolls dans une surcouche AgenticOS, puis montre la délégation et la validation du résultat par Ingrid. Tu verras aussi le Free Models Router, le basculement entre modèles gratuits en cas de surcharge et les vrais rate limits d’OpenRouter : 20 requêtes par minute, 50 par jour sans paiement et jusqu’à 1 000 par jour après un dépôt de 10 $. Si tu cherches à faire tourner Hermes Agent gratuitement tout en comprenant ses limites et ses compromis, cette vidéo te donne la méthode complète.

━━━━━━━━━━━━━━━━━━━━━━━━━━━

PROMPT :

Mon Hermes Agent tourne dans un conteneur Docker sur un VPS Hostinger (image
nousresearch/hermes-agent). Je te donne l'accès SSH à ce VPS et ma clé API
OpenRouter. Fais deux choses, entièrement via SSH + docker : connecte Hermes à
OpenRouter, puis débloque TOUS les modèles gratuits utilisables (compatibles
tool-calling) dans le sélecteur, plus openrouter/free.

Ce qu'il faut savoir sur ce setup, pour t'éviter de deviner :
Hermes tourne dans un conteneur : repère-le avec `docker ps` (image
  nousresearch/hermes-agent). Toutes les actions se font DEDANS (docker exec).
Sa config vit dans HERMES_HOME=/opt/data : config /opt/data/config.yaml,
  clés /opt/data/.env, cache du sélecteur /opt/data/cache/model_catalog.json.
Le sélecteur ne lit pas tout /v1/models : il part d'une liste curatée puis
  filtre par prix (gratuit) et support des outils. Pour en montrer plus, on
  étend cette liste via un manifeste local + le bloc model_catalog.
Ne me demande jamais de resaisir mes secrets, ne les affiche jamais, ne les
  écris dans aucun log.

Fais, dans cet ordre, en vérifiant la vraie structure du conteneur avant :
1. Sauvegarde /opt/data/config.yaml (dans le conteneur).
2. Connecte OpenRouter : mets `provider: "openrouter"` et
   `base_url: "https://openrouter.ai/api/v1"` dans le bloc `model:` de
   /opt/data/config.yaml, et écris ma clé dans /opt/data/.env sous
   OPENROUTER_API_KEY (sans l'afficher).
3. Interroge https://openrouter.ai/api/v1/models et retiens tous les modèles
   GRATUITS (pricing prompt ET completion = "0") qui listent "tools" dans
   supported_parameters. Ajoute openrouter/free.
4. Écris un manifeste /opt/data/openrouter-free.json au format EXACT :
   {"version": 1, "providers": {"openrouter": {"models": [{"id": "..."}]}}}
   Il doit contenir les modèles OpenRouter déjà curatés PLUS tous les
   gratuits+outils ci-dessus.
5. Ajoute dans /opt/data/config.yaml le bloc :
   model_catalog:
     enabled: true
     url: "file:///opt/data/openrouter-free.json"
6. Supprime le cache /opt/data/cache/model_catalog.json.
7. VÉRIFIE réellement (ne te fie pas au fichier écrit) : compte les modèles
   gratuits que le sélecteur montrera pour openrouter, avant et après. Tu peux
   le faire en appelant hermes_cli.models.fetch_openrouter_models(
   force_refresh=True) avec le python du conteneur
   (/opt/hermes/.venv/bin/python, PYTHONPATH=/opt/hermes). Confirme que (a) le
   nombre de gratuits a augmenté et (b) openrouter/free est présent. Si l'une
   échoue, NE me dis PAS que c'est bon : dis ce qui a raté.
8. Ne désactive jamais le filtre outils : un modèle sans "tools" plante à la
   sélection. Dis-moi combien de gratuits ont été exclus faute d'outils.

À la fin : dis-moi de relancer Hermes et donne-moi le compte de gratuits
AVANT / APRÈS.
