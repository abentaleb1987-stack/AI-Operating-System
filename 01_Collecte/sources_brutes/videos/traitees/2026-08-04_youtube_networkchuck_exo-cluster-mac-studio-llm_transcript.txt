If I am not mistaken, this kind of clustering does not use the compute power of all nodes in parallel; instead, it uses memory in parallel when working on a single prompt.

The model split distributes layers among nodes sequentially. For example, if you have 100 layers, then layers 1–20 go to node 1, layers 21–40 go to node 2, and so on, with layers 81–100 assigned to node 5.

Execution runs sequentially: first, node 1 processes its assigned layers, then its result is passed to node 2, and so forth. This means the nodes in such a cluster are utilized in sequence rather than in parallel.

Parallel compute capacity becomes available when running multiple prompts simultaneously. Up to five prompts can be processed in a pipeline—for instance, when the first prompt moves to node 2, node 1 begins working on the second prompt, and so on.

Given this, this type of clustering does not accelerate small models that fit within a single node's memory. Additionally, for larger models, you won't see significant acceleration when running a single prompt at a time. However, this clustering approach allows you to run large models that wouldn't fit into a single node’s memory and potentially achieve better compute efficiency when processing multiple prompts in parallel.
