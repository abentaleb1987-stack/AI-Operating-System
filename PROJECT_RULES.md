# Regles du projet

## Principe central

La base doit rester synthetique, fiable et exploitable.

## Cycle officiel

Source -> Collecte -> Qualification -> Fiche de veille -> Validation -> Mise a jour de la fiche permanente -> Archivage

## Regles de connaissance

- Une source brute ne modifie jamais directement une fiche permanente.
- Toute nouvelle source produit d'abord une fiche de veille ou une note de qualification.
- La fiche permanente n'est jamais reecrite entierement.
- Chaque mise a jour de fiche permanente doit integrer uniquement les differences validees.
- Les informations marketing, speculatives, non verifiees ou contextuelles restent dans la veille.
- Les decisions strategiques doivent etre datees et rattachees a une justification.

## Regles Git

- Utiliser des noms de fichiers courts, stables et explicites.
- Privilegier les dossiers et fichiers compatibles avec une automatisation future.
- Eviter les renommages inutiles.
- Archiver au lieu de supprimer lorsqu'une trace de decision est utile.

## Architecture documentaire

- Instructions = contrat global du projet.
- Standards = regles transversales.
- Frameworks = processus operationnels.
- Templates = formats d'application.
- IA = connaissances capitalisees.
- Scripts = automatisation.
- System = gouvernance technique.

Les agents IA doivent respecter les Instructions, les ADR, les Standards, les Frameworks et les Templates. Ils ne doivent pas redefinir l'architecture sans validation.
